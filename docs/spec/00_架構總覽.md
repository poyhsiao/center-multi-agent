# 混合式多租戶 AI SaaS 平台 — 架構總覽

> **版本：** v0.1 (草稿)  
> **日期：** 2026-05-07  
> **狀態：** 已完成架構確認，等待實作規格展開

---

## 1. 系統定位

本系統是一個**混合式多租戶 AI SaaS 平台**，結合：

- **雲端管理層（Server）**：負責身份驗證、授權、LLM 推理協調、組織知識管理、系統治理
- **本地代理層（Client Agent）**：運行於用戶設備（Mac / Windows / Linux），具備本地記憶、人格設定、MCP 協議支援及 OS 自動化能力

**核心設計原則：Client 端操作優先，所有操作都需連網確認可使用權。**

## 3. 技術選型矩陣

### 3.1 後端核心元件

| 元件 | 技術選型 | 備選方案 | 決策理由 |
|------|----------|----------|----------|
| API Gateway | Kong / APISIX | AWS ALB / Nginx | 雲端無關、插件豐富、Rate Limit/LB 內建 |
| 認證服務 | JWT + Refresh Token | OAuth2 + OIDC | 簡單夠用、Client 端驗證方便 |
| 資料庫 | PostgreSQL + RLS | MySQL / CockroachDB | RLS 支援好、PGVector 原生、成熟穩定 |
| 向量資料庫 | PGVector / pgvecto.rs | Qdrant / Milvus | 與 PG 同庫，运维簡單 |
| 快取/工作階段 | Redis | Dragonfly | 成熟、Redis Cluster 支援廣 |
| 訊息佇列 | Kafka | RabbitMQ / Redis Streams | 事件驅動擴展性、Webhook 訂閱 |
| 即時通知 | SSE (Server-Sent Events) | WebSocket | 簡單、單向足夠、HTTP/2 友好 |

### 3.2 Client Agent 元件

| 元件 | 技術選型 | 備選方案 | 決策理由 |
|------|----------|----------|----------|
| 客戶端框架 | Tauri (Rust) | Electron | 記憶體輕量、安全性高、效能佳 |
| 本地資料庫 | LanceDB | SQLite + chroma | 向量搜尋一站式、離線優先 |
| OS 自動化 | CUA Driver (macOS/Windows) | AppleScript/PowerShell | 跨平台、模型驅動 |
| MCP 客戶端 | 自研 | -- | OpenAPI 格式、Server/Client 雙向 |

### 3.3 部署架構

| 環境 | 部署方式 | 隔離策略 |
|------|----------|----------|
| 測試環境 | Docker Compose (一鍵部署) | Schema-per-Org |
| 開發環境 | Docker Compose + Local Dev | Schema-per-Org |
| 生產環境 | Kubernetes / Cloud Native | Database-per-Org (重要租戶) / Schema-per-Org (普通租戶) |

```

  ├── 全域模型配置
  ├── 全域稽核日誌查閱

  │
  ├── Org Admin × N
```

## 5. Client Agent 的定位說明

Client Agent **不是傳統意義的 AI Agent（自己會做複雜決策）**，而是：

> **一個受 Server 控制的本地代理執行器（Controlled Local Proxy）**

### 5.1 運作模型

```
使用者意圖
    ↓
Client Agent 收集
  - 使用者 Prompt
  - Persona 設定
  - 本地 RAG 結果 (LanceDB)
  - 本地 Skills/MCP 上下文
    ↓
連網驗證 (每個 Operation 前)
  - Token 有效性
  - 權限檢查
  - 設備指紋比對
  - Server 撤銷名單查詢
    ↓ (通過)
Server LLM 推理
  - 路由至合適模型
  - 整合組織共享知識
  - 產生回應/操作指令
    ↓
Client Agent 執行
  - 執行 Server 允許的操作
  - 呼叫本地 MCP/Tools
  - 寫入本地 LanceDB
    ↓
結果回傳並記錄
```

### 5.2 離線行為

| 情境 | Client 行為 |
|------|-------------|
| 連線中 | 正常流程，所有操作連網驗證 |
| 連線中，Server 網路錯誤 | 佇列操作（Priority: Org Admin > User），重試 3 次後通知用戶手動處理 |
| 離線（網路完全中斷） | 所有操作排入佇列，等待用戶手動連網觸發 |

> **Client Agent 不做本地 LLM 推理**。所有智慧來自 Server。

## 6. 安全性模型

### 6.1 身份驗證流程

```
1. 使用者登入
     ↓
2. Auth Service 驗證 (密碼 / SSO / TOTP)
     ↓
3. 核發 Access Token (14天有效期，可調整) + Refresh Token
     ↓
4. Access Token 與設備指紋綁定
     ↓
5. Client 每次 Operation 前校驗 Token + 指紋
     ↓
6. Server 可隨時撤銷 Token (Redis Blacklist)
```

### 6.2 Emergency Access 機制

- Super Admin 因業務需求需讀取 Org 資料時，触发以下流程：
  1. 系統記錄完整存取日誌（永久保留）
  2. 即時通知 Org Admin（In-app + Email）
  3. Org Admin 可檢視 Super Admin 的所有操作紀錄

## 8. 系統邊界與整合

### 8.1 系統邊界內

- Org > Dept > User 全生命週期管理
- RBAC 權限管理
- Client Agent 交付與管理
- 組織共享知識庫（含審核流程）
- 個人本地知識庫（離線可用）
- LLM 模型閘道（集中 GPU、路由、計價）
- MCP/Skills 同步與管理
- 操作稽核與 Super Admin Emergency Access

### 8.2 整合預留（系統邊界外）

| 整合項目 | 方式 | 優先級 |
|----------|------|--------|
| AD/LDAP (SSO) | SAML/OIDC | P1 |
| Slack / Teams | Webhook + Bot | P2 |
| CRM / ERP | MCP Server | P2 |
| 外部 API | MCP Server | P2 |
